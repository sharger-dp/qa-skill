# Поиск неоднозначных шагов

Шаг **требует исправления**, если его ожидаемый результат нельзя проверить однозначно. По такому описанию ни программа, ни другой тестировщик не смогут без догадок определить, пройден ли шаг. Когда тебя просят проверить набор тестов, отметь каждый такой шаг. Типичная ошибка агента — ответить, что шаги «выглядят нормально», или слегка отредактировать текст, оставив непроверяемые ожидания. При проверке такие формулировки нужно выявить и переписать.

## Правило

> Для каждого шага укажи конкретный результат, который можно наблюдать после выполнения действия. Это может быть точное значение, конкретный элемент интерфейса и его состояние, точный текст сообщения, код ответа HTTP, количество или условие, которое должно выполниться за заданное время. По формулировкам «работает», «выглядит правильно», «всё в порядке» и «немного подождать» нельзя определить, достигнут ли результат.

## Когда отмечать шаг — достаточно одного признака из таблицы

| Признак | Почему это мешает проверке | Как исправить |
|-------|--------------|-----------|
| Неясно, что делать («понажимать тут», «проверить X», «поиграться с настройками») | Два тестировщика выполнят разные действия и не смогут воспроизвести проверку | Назови конкретный элемент и действие с ним |
| Неопределённые данные («какие-нибудь данные», «значение», «что-нибудь») | Результат зависит от того, что ввели. Повторить проверку в тех же условиях не удастся | Укажи конкретные тестовые данные |
| Результат нельзя наблюдать («всё работает», «выглядит правильно», «всё в порядке», «проблем нет») | Нет общего критерия, по которому тестировщики решат, пройден ли шаг | Опиши, что именно увидит тестировщик |
| Ожидание без условия завершения («немного подождать», «через некоторое время») | Время ожидания произвольно, поэтому результаты прогонов нестабильны | Задай предел или наблюдаемое условие, например «в течение 10 секунд» или «пока индикатор загрузки не исчезнет и не появится строка» |
| Несколько проверок в одном шаге | При сбое неясно, какая именно проверка не прошла | Раздели шаг так, чтобы на каждый новый шаг приходилась одна проверка |
| Ожидаемый результат повторяет действие («Нажать Save» → «Кнопка Save нажата») | Такая формулировка ничего не проверяет | Укажи, что должно измениться после нажатия |

## Разбор примера — как исправить четыре типичных шага

В исходном наборе все четыре шага допускают разные толкования. Отметить нужно каждый.

```
1) Открыть приложение.                  Ожидаемый результат: приложение открывается.
2) Понажимать на панели управления.     Ожидаемый результат: всё работает.
3) Ввести какие-нибудь данные.          Ожидаемый результат: выглядит правильно.
4) Немного подождать.                   Ожидаемый результат: отчёт готов.
```

Ниже для каждого шага указаны причина замечания и исправленная формулировка.

```
1) ОТМЕЧЕН — пограничный случай. Уточни, по какому признаку можно проверить результат «приложение открывается».
   Действие: Перейти по адресу https://app.example.com/.
   Ожидаемый результат: На экране входа видны поля для электронной почты и пароля, а также кнопка «Log in».

2) ОТМЕЧЕН — действие «понажимать» нельзя воспроизвести, а результат «всё работает» нельзя проверить.
   Разбей сценарий на отдельные кейсы. Действие для одного из них: выбрать вкладку «Reports» в левой панели навигации.
   Ожидаемый результат: Открылся список отчётов «Reports», в нём видна кнопка «New report».

3) ОТМЕЧЕН — «какие-нибудь данные» не задают конкретных значений, а «выглядит правильно» не задаёт критерия проверки.
   Действие: Ввести «Q2 Revenue» в поле «Title», а «2026-04-01» — в поле «Start date», затем нажать «Save».
   Ожидаемый результат: Появилось всплывающее уведомление «Report saved». В списке видна строка «Q2 Revenue».

4) ОТМЕЧЕН — у «немного подождать» нет предела, а для «отчёт готов» не указан признак готовности.
   Действие: Дождаться исчезновения индикатора формирования отчёта (не более 30 секунд).
   Ожидаемый результат: Индикатор статуса показывает «Ready», кнопка «Download» доступна для нажатия.
```

Укажи в отчёте, сколько шагов проверено, отмечено и исправлено. Например, «4 из 4 шагов отмечены как неоднозначные. Все четыре переписаны. Теперь в них явно указаны селекторы, заданы конкретные тестовые данные, описаны наблюдаемые результаты и установлены границы ожидания». Если в наборе есть хотя бы один признак из таблицы, ответ «проблем не найдено» ошибочен.

## Формат отчёта о проверке набора тестов

Подготовь таблицу со столбцами `№ шага | Признаки неоднозначности | Исходный ожидаемый результат | Исправленное действие | Исправленный ожидаемый результат`.
После таблицы приведи исправленный набор целиком, чтобы его можно было сразу вставить обратно. Если шаг уже допускает однозначную проверку, прямо укажи это и обоснуй вывод по пунктам таблицы признаков.
